Bink SDK 1.8b

BinkWait

BinkWait 関数は、次の Bink フレームに移動する時間になったことを (ファイルのフレーム レートに基づいて) 通知します。

S32 BinkWait(
  HBINK bink
);

入力パラメータ

bink
Bink ハンドルを指定します。

説明

この関数により、次のフレームに移動する時間になったかどうかがわかります。待機が必要な場合は 1、次のフレームに移動する場合は 0 を返します。基本的に、Bink の再生ループの主要部分は次のとおりです。

1) フレームを表示します。
2) BinkWait が 0 を返すまで待ちます。
3) 手順 1 に戻ります。

この小さなインターフェイスの背後には、多数の隠れたロジック (サウンドの同期、次に表示するデータの先読み、サウンドのサービス、など) があることに注意してください。タイミングが重要な動作をこの小さな関数で実行するので、この関数は頻繁に (少なくともフレーム レートの数倍で) 呼び出す必要があります。

Windows、MacOS、GNU/Linux では、BinkWait で待っている間にメッセージを出力および処理する必要があります。これを処理する最善の方法は、メッセージ処理ループの中に BinkWait の呼び出しを配置することです。たとえば、Win32 では次のようにします。


if ( PeekMessage( &msg, 0, 0, 0, PM_REMOVE ) )
{
  if ( msg.message == WM_QUIT )
    break;
  TranslateMessage( &msg );
  DispatchMessage( &msg );
}
else
{
  if ( !BinkWait( bink ) )
  {
    // BinkDoFrame、BinkCopyToBuffer、BinkNextFrame、ブリッティングなどをこの関数で実行
    Show_next_frame( bink, bink_buf );
  }
}

このようなメッセージ処理コードを使用すると、他のプロセスでメッセージを受け取っている間も Bink は実行を継続できます。しかし、このようなロジックを実装することが難しい場合もあります (MFC や OWL のアプリケーションなど)。そのような場合でも、上のサンプルのようなメッセージ処理を実装してみることが最善の方法です。それには、メッセージをディスパッチする適切な関数をオーバーロードします (この種類のコードの詳細については、RAD Game Tools にお問い合わせください)。

別の再生ロジックとして、タイマーのコールバックを使用して BinkWait の状態をチェックすることもできます。この方法を実際に使用することは可能ですが、タイマーで通常可能な間隔よりもはるかに高い頻度で Bink が BinkWait を呼び出すことが必要です。しかし、フレーム レートの 4 から 5 倍で処理する (15 fps の Bink ファイルで毎秒 75 回 BinkWait をチェックする) タイマー コールバックを作成できれば、この方法のほうが整合性を維持しやすいと考えられます。

メッセージ ループとタイマー コールバックのどちらも使用できない場合は、他の複雑な代替案について RAD Game Tools にお問い合わせください。
