# Аудит PainEngine-Source/Source (2026-11-19)

## Вывод

Это обширный исторический снимок исходного кода PainEngine/Painkiller, однако он **не является полным деревом исходников Windows/VS2003, которое можно сразу собрать**, а имеющихся данных недостаточно, чтобы подтвердить совместимость ABI полученного движка с установленной Black Edition. Не используйте результаты сборки из этого дерева для замены оригинальных DLL игры.

Дерево содержит 6815 файлов (699,4 МиБ) в каталогах Engine, D3Dev, PainKiller, PainEditor, PKServer, PKTVProxy, а также плагины, инструменты и сторонний код/библиотеки. Коммит исходного checkout: `dfc3a62ce1bb40db90cb4951dc5ab6273c7ec651`. В начале аудита отслеживаемые Git файлы не имели изменений; ближе к концу в `Source/PainEditor/Game/Main.cpp` обнаружилось изменение двух строковых литералов на польском/французском языке (время изменения 02:26:51). Аудит не записывал данные в этот checkout и не затрагивал это параллельное изменение.

## Подтверждения

- `TRANSGAMING_README` датирован 5 июля 2005 года. В нём описывается ранний этап подготовки исходников/сборки Morphine и прямо говорится, что при компиляции остаются нерешённые проблемы в `Engine/Engine.cpp`, а дальнейшие проблемы ещё не исследовались.
- В `PK.sln` указаны Visual C++ Express 2005 и формат решения 9.00. Среда VS2003 (7.10) отклоняет его как решение более новой версии. Отдельные файлы `.vcproj` указывают версию 7.10 и открываются в VS2003 через изолированную обёртку формата 8.
- Каталог `Source\Base` отсутствует. В `Engine.vcproj`, `D3Dev.vcproj` и `PainKiller.vcproj` подключается `..\Base`; старый `PK.sln.old` также ссылается на отсутствующий проект `Base\Base.vcproj`. Это отсутствующий проект/зависимость, а не путь, который есть в другом месте предоставленного дерева.
- В `Engine\Core\TypeTraits.h:35` находится безусловная директива `#error PC` в ветке, используемой для Win32. В предоставленном виде первая единица трансляции C++ завершается ошибкой при сборке в VS2003. В конфигурации Release проекта также отсутствуют определения `TRANSGAMING` и `TRANSGAMING_WINDOWS`, используемые конфигурацией Debug.
- Для пользовательских шагов сборки Engine Release требуется компиляция шейдеров. Первая обычная сборка завершается ошибкой, поскольку `fxc` не найден; явный запуск включённого в комплект `Tools\fxc.exe` приводит к `Failed to create D3D device` в headless XP VM. Другие пользовательские шаги компиляции шейдеров вызывают `..\..\example\Data\Shaders\vsa`, которого в этом снимке также нет.

## Попытки сборки в VS2003 (XP VM)

- Всё решение целиком: отклонено, поскольку `PK.sln` создан в VS2005.
- Engine Release: проект открывается; сборка завершается ошибкой до компиляции C++ на шаге `FX Compile: Water`. В изолированном диагностическом проекте, где исключены пользовательские шаги сборки (исходный код не изменялся), VS2003 доходит до `Engine.cpp` и сообщает ошибку на `TypeTraits.h:35: #error PC`. Диагностическая копия, в которой добавлены отсутствующие определения платформы, всё равно завершается на той же безусловной ошибке. `Engine.dll` не создан.
- D3Dev Release: проект открывается и успевает скомпилировать все три указанные единицы трансляции, после чего сообщает ту же ошибку `TypeTraits.h:35: #error PC`; сборка не удалась. `D3Dev.dll` не создан.
- PainKiller Release: проект открывается и завершается ошибкой в `Main.cpp` из-за той же ошибки TypeTraits. Сборка не удалась. EXE не создан.

Журналы сборки: `full-solution-vs2003.log`, `engine-vs2003-build.log`, `engine-cpp-diagnostic.log`, `engine-cpp-audit.log`, `d3dev-vs2003-build.log`, `painkiller-vs2003-build.log`. Диагностические копии проектов создавались только в `C:\PainEngine\SourceAudit` внутри VM; недавно добавленная папка с исходниками не изменялась.

## Проверка совместимости

Оригинальная установленная `D3Dev.dll` экспортирует ровно две функции: `CreateDevice` и `DestroyDevice`. Эти имена совпадают с двумя экспортами в `D3Dev.def` из снимка. Это подтверждает только совпадение внешнего интерфейса плагина. Оригинальная `Engine.dll` размером 4,44 МиБ содержит 2877 экспортируемых имён. Поскольку из этих исходников не удалось собрать `Engine.dll`, сравнить бинарные экспорты/ординалы/сигнатуры и подтвердить совместимость ABI невозможно. В снимке присутствует Lua-привязка `RotateQuatByAxisAngle` и значительная часть соответствующих подсистем движка. Поэтому он ценен как справочный материал, но это не доказывает, что перед нами точная версия исходников для Black Edition.

Оригинальные DLL игры аудитом не заменялись и не изменялись. Их текущие хеши и хеши копий, использовавшихся только для чтения, указаны в `install-hashes.json`. В `dumpbin` передавались только DLL-копии из папки аудита.

## Что требуется для пригодной к сборке версии исходников

Нужно восстановить отсутствующий компонент Base, завершить ветку Win32 в TypeTraits, исправить определения платформы для Release, восстановить или предоставить компилятор шейдеров и связанные инструменты/результаты (в том числе ожидаемую папку `vsa`), затем пересобрать проекты и сравнить PE-экспорты, декорированные имена, раскладку классов и поведение во время работы с установленной оригинальной версией. Это необходимые исправления исходников и сборочной системы; данный аудит их в новую папку с исходниками не вносил.
